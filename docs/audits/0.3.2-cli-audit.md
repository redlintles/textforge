# Internal audit: the `txf` command-line program (0.3.2)

Scope: `src/main.rs`, `src/utils/cli.rs` and the parts of the library they
call, checked against the current engine (0.3.2 on `main`, `b3cb952`). The CLI
had seen little work since before 0.2.0 while the engine gained the static
context, file instructions, profiles and the line rules of `docs/lines.md`.
Every finding was reproduced with the built binary before any change. Timings
below come from a debug build in the `textforge-dev` container; the release
comparison is in [the CLI benchmark](../benchmarks/cli/README.md).

| # | Kind | Finding | Severity |

| 2 | Bug | `__INPUT_FILE__` is always empty in `txf` | High |

| 4 | Bug | `--max-iterations` and `.txfrc` `max_iterations` accept byte units | Medium |
| 5 | Bug | Errors in profile flags are reported as coming from `.txfrc` | Low |
| 6 | Usability | `-` is not standard input/output (`-o -` creates a file named `-`) | Medium |

## 1. Chunk mode is quadratic

**Cause.** `process_input_by_chunks` finds each chunk boundary with
`get_safe_utf8_char_index(i * size, input)`, which walks the text from its
first character every time.

**Reproduction.** 51 MB of text, pipeline `tua;`: `-r all` 0.32 s,
`-r chunk-65536` 1018 s (debug build).

**Fix.** One forward pass over `char_indices` that cuts the text as it goes.

## 2. `__INPUT_FILE__` is always empty

**Cause.** `txf` reads the input itself and calls `process_all(&str)`, which runs
the pipeline without an input file.

**Reproduction.** `atb "{{__INPUT_FILE__}}|";` with `-i in.txt` gives `|abc`;
expected `in.txt|abc` (the value `process_file` gives).

**Fix.** Run through a processor method that takes the input path (also for the
debug trace and watchers).

## 3. Panic on a closed pipe

**Cause.** The result is written with `print!`, which panics on `EPIPE`.

**Reproduction.** `txf -f rpt.textforge | head -c 5` prints
`panicked … failed printing to stdout: Broken pipe`.

**Fix.** Write through `io::Write` and end quietly with status 0 when the reader
has gone away, like other Unix tools.

## 4. Iteration limits accept byte units

**Cause.** `parse_limit` parses every limit with `parse_bytes`: `--max-iterations
10KiB` means 10240 iterations, and `--max-iterations many` answers "unknown size
unit; use B, KiB, MiB or GiB". `docs/txfrc.schema.json` already allows only
digits or `unlimited` for `max_iterations`.

**Fix.** A count parser (`parse_count`) for `max_iterations`, in flags and
`.txfrc`.

## 5. Flag errors blamed on `.txfrc`

**Reproduction.** `--spool-threshold 1` prints `in: txfrc`.

**Fix.** Errors of a flag name the flag.

## 6. `-` as standard input and output

**Reproduction.** `-i -` fails with "the input file `-` does not exist";
`-o -` writes a file called `-`.

**Fix.** `-` means standard input for `--input` and standard output for
`--output`.

## 7. Input before pipeline

**Cause.** `run()` reads all of stdin before loading the pipeline.

**Reproduction.** With an invalid pipeline and a slow writer on stdin, the error
appears only when stdin closes (3 s in the test). Run interactively without
`-i`, `txf` waits in silence.

**Fix.** Load and validate the pipeline first; when stdin is a terminal, print a
one-line hint on stderr.

## 8. Line mode and `--chomp` ignore most terminators

**Cause.** `process_input_line_by_line` splits on `\n` and `split_final_newline`
knows `\n` and `\r\n`. `docs/lines.md` (and `__LINES__`, the `*ln` instructions,
`onln`) also recognize CR, VT, FF, NEL, LS and PS.

**Reproduction.** `printf 'a\rb\rc' | txf -f atb.textforge -r line` runs the
pipeline once.

**Fix.** Use the shared scanner of `src/utils/lines.rs` in both.

## 9. Chunk boundaries and chunk errors

**Reproduction.** `ab\r\ncd` with `chunk-3` and `atb X;` gives `Xab\rX\ncd`. An
error in a chunk names only the instruction, while line mode says
`input line N ›`.

**Fix.** A boundary never falls between `\r` and `\n` (the chunk takes the `\n`);
errors start with `input chunk N ›`.

## 10. Debug trace of pieces

**Fix.** In `line` and `chunk` mode each trace is preceded by the piece it
belongs to; a pipeline without instructions says so.

## 11. Bytecode detection

**Fix.** `--mode auto` (new default) reads the first bytes, like `ppjn`; `t` and
`b` still force a format.

## 12. Compile, decompile, check

**Fix.** Subcommands `txf compile`, `txf decompile` and `txf check`, built on
`write_to_bytecode_file`, `write_pipeline_to_file` and the loaders.

## 13. Watchers

**Fix.** `--watch METRIC` (repeatable, or `all`) and `--watch-report PATH`, with
the built-in metrics of the portable API.

## 14. Packaging

**Fix.** The `cli` feature enables `bytecode` and `watchers` (neither adds a
dependency).

## 15. Copies of the input

**Cause.** The input `String` is copied into the engine (`process_all(&str)`),
and `line`/`chunk` collect every processed piece in a `Vec<String>` before
`join`.

**Fix.** Hand the owned input to the engine; append pieces to one buffer.

## 16. Atomic output

**Fix.** Regular output files are replaced through `write_atomically`, as `wtf`
does; other targets (`/dev/null`, a FIFO) are written directly.

## 17. Exit codes

**Fix.** 0 success, 1 the pipeline failed on the text, 2 usage or configuration
error, 3 the pipeline could not be loaded, 4 input or output error. Documented
in the help and in `docs/cli.md`.

## 18. Help and documentation

**Fix.** Descriptive help with examples, value names, both extensions of each
format, and a CLI guide (`docs/cli.md`).

## 19. Panicking calls in `main.rs`

**Fix.** Read the arguments without `unwrap`; the pipeline format is an enum.

## Not changed

- `.txfrc` is still looked up in the working directory (decided in the 0.3.0
  specification, §10.3), while file instructions start from the pipeline
  directory. Documented in `docs/cli.md`.
- `line` and `chunk` with an empty input run the pipeline zero times (an empty
  text has no lines and no chunks); `all` runs it once. Documented.
- Shell completions would need `clap_complete`, a new dependency (human
  approval).
- `src/bin/atp-game.rs` and `src/bin/atp-shell.rs` are placeholders kept by the
  maintainer.
